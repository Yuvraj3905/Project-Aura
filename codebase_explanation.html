Project Aura Codebase

An interactive, detailed guide to the autonomous, stateful "Sales Engineer" agent codebase.

Overview & Architecture

Project Aura is a 100% open-source, locally run "Sales Engineer" agent. It ingests large internal engineering documents, tracks multi-day client conversations, and answers technical questions without hallucinating. It uses local inference and no paid LLM APIs.

1. Web Frontend & API /web

Next.js App Router (UI + API + WebSocket)

The web/ directory contains the Next.js application, which acts as the main user interface, API gateway, and handles background job enqueuing.

app/ Contains the React UI components (chat interface, document upload, dashboard) and Next.js API routes (/api/upload, /api/chat).
worker/ Node.js entrypoint for the pg-boss consumer. Processes background jobs enqueued by the API.
lib/ Shared utilities: database connection pools, queue management, and PostgreSQL NOTIFY/LISTEN helpers for WebSockets.
server.ts Custom Next.js server to support WebSocket connections for real-time document processing updates.

Key Responsibilities:

  • Uploads: Receives files, saves them, and enqueues a process_document job using pg-boss.
  • Chat Interface: Communicates with Rasa (dialogue) and ml-service (streaming responses via SSE).
  • Dashboard: Operations view for monitoring jobs, documents, sessions, and tickets.

2. ML Service /ml-service

Python / FastAPI (Embeddings, RAG, Ingestion)

The ml-service/ handles all the heavy machine learning tasks: document chunking, summarization using local Ollama models, embedding generation, and Retrieval-Augmented Generation (RAG).

app/main.py FastAPI application entrypoint defining endpoints (/embed, /ingest, /answer).
app/embeddings.py Manages the Sentence Transformers model (bge-small-en-v1.5, 384-dim) for text vectorization.
app/llm.py & cache.py Interface to Ollama (llama3:8b) for text generation and Redis caching logic.
app/pipeline/ Extraction, hierarchical chunking, summarization, and storage into pgvector.
app/rag/ Retrieval logic (cosine similarity search) and streaming response generation (Server-Sent Events).

3. Dialogue Manager /rasa

Rasa (NLU + Core + Custom Actions)

The rasa/ directory manages the conversation flow, intent recognition, and multi-turn statefulness.

data/ Contains NLU training data (intents), conversation rules, and stories.
actions/ Custom Python action server (runs on port 5155). Executes business logic, forms (e.g., ticket collection), and decides when to trigger the ML service.
domain.yml Defines the bot's universe: intents, entities, slots (memory), responses, and forms.

Persistence: Rasa sessions are persisted in Postgres (tracker store), allowing users to resume conversations even days later.

4. Database & Queue /db

PostgreSQL + pgvector + pg-boss

Postgres acts as the central nervous system for state and vector storage.

db/init.sql Bootstraps the database and extensions upon initial Docker container startup.
db/migrations/ SQL scripts to create tables: documents, vector chunks, support_tickets, and Rasa event tables.

Key Components:

  • pgvector: Used to store and perform cosine similarity search on document embeddings.
  • pg-boss: A Postgres-based job queue for handling asynchronous document ingestion without needing a separate message broker like RabbitMQ.

5. Key Data Flows

A. Document Ingestion Flow

  1. User uploads file via UI → web/app/api/upload/route.ts
  2. File is saved, and a process_document job is added to Postgres via pg-boss.
  3. Node worker picks up the job and sends a REST call to ml-service /ingest.
  4. ml-service extracts text, runs hierarchical summarization via Ollama, chunks it, generates embeddings, and saves to pgvector.
  5. Postgres fires a NOTIFY kb_ready event.
  6. Next.js custom server catches NOTIFY and pushes via WebSocket to update the UI instantly.

B. Chat & RAG Flow

  1. User sends a message → web/api/chat forwards to Rasa.
  2. Rasa predicts intent (e.g., tech_query).
  3. Rasa Custom Action returns a stream directive to the web UI.
  4. Web UI opens a Server-Sent Events (SSE) connection to /api/chat/stream → ml-service /answer/stream.
  5. ml-service does vector search (pgvector), finds relevant chunks, and prompts Ollama.
  6. Response streams token-by-token back to the UI. If similarity is too low (< 0.45), guardrail blocks hallucination.
